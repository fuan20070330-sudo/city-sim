## 二、演示故事线

标准场景：**滨江核心区 · 火灾链式响应**

1. 滨江智慧物流园发生三级火灾，需要两辆消防车与一辆物资车。
2. 老城社区同时发生医疗急救，需要一辆救护车。
3. 调度器按负载均衡策略完成任务分配，多类智能体同时出发。
4. 车辆途中遇到道路施工中断，引擎自动识别受影响路线。
5. 车辆从当前位置重新规划，事件流与地图路径同步更新。
6. 多车到场后协同处置，响应时间、覆盖率和利用率发生变化。
7. 全部任务完成后进入复盘，可拖动时间轴回看派车、断路与重规划。

## 三、技术创新点

1. **确定性数字沙盘**：核心推进不使用随机数，同一输入可完全复现，便于算法验收与答辩演示。
2. **Worker 隔离**：路径搜索、任务分配和指标计算不阻塞 Canvas 渲染。
3. **算法可解释对比**：同时展示 ETA、路径长度和搜索探索节点数。
4. **多智能体能力编成**：不是“一事件一车辆”，而是按消防、医疗、物资能力组合派发。
5. **事件驱动的动态重规划**：断路不是视觉动画，而是真实改变图结构、路线和后续指标。
6. **离线优先**：地图、数据、存储、仿真、回放均可在无网络环境下运行。

## 四、测试与质量证据

- TypeScript 严格模式：`tsc --noEmit`
- 单元测试：10 条，覆盖 A*/Dijkstra 最优代价、断路绕行、多智能体编成、确定性、重规划、事件/资源/道路编辑、算法对比和场景校验。
- 端到端测试：3 条，覆盖单步派车与对比、剧情演示自动重规划、本机场景保存。
- 生产构建：Vite 产出独立 Worker chunk、CSS 与 JS 静态资源。
- 视觉检查：1366×768 桌面视口无页面级横向溢出。

## 五、答辩时建议主动说明的限制

- 这是调度推演沙盘，不是真实 GIS 交通仿真，也不用于真实应急决策。
- 交通模型简化为路段通行时间系数，未建模信号灯与跟驰。
- WebSocket 只是可选的远程监看广播接口，GitHub Pages 不提供 WebSocket 服务。
- 所有场景数据均为虚构；项目不包含密钥和个人数据。
